# Deployment Governance

## Applicability

本合约适用于环境搭建、基础设施变更、目标环境配置写入、构建或发布产物交付、服务部署/启停/升级/恢复、凭据材料化，以及其他会改变目标环境的操作。纯本地开发和不改变目标环境的只读分析不适用。

规则保持平台中立；具体环境、工具和长期限制来自根目录 `PROJECT-CONTEXT.md`，单次目标、授权和结果来自对应 Task。

## Responsibility

- 项目经理创建部署 Task 和环境变更授权章节，核对其符合 Sprint、本地 DP 与项目规则，并记录人工 Owner 的明确授权。
- 平台工程师填写技术执行边界，在授权范围内执行并维护 attempt 与证据。
- 人工 Owner 批准完整的环境变更范围，不负责代替 Agent 编写技术内容。
- Acceptance Owner 核对授权、执行和结果，不修改授权，也不得与 Task Owner 相同。
- 同一 Agent 可以在明确切换角色后起草 Task 并补充技术边界，但不能代替人工授权或独立验收。

## Environment Change Authorization

人工授权针对有边界的环境变化，不针对某一条命令。部署 Task 按模板记录：

- `Target and Change`：目标环境、操作对象、固定交付输入和预期变化。
- `Execution Boundary`：允许的影响、部署执行包络、attempt、关键禁止事项、停止条件与恢复方式。
- `Approval`：人工 Owner、日期和可追溯授权来源；批准前为 `Pending`。

`Approval` 为 `Pending` 时，只允许本地准备和授权范围所需的非敏感只读检查，不得执行目标环境写操作。未明确覆盖的有副作用操作默认不允许。人工授权能够明确对应完整范围即可，不要求固定口令。

部署执行包络必须一次写明允许的预检、构建或上传、迁移、服务更新、健康检查、只读诊断、同范围局部修复、重试和恢复。除非人工 Owner 为该 Task 明确批准不同额度，默认预算为：目标环境只读诊断最多 5 次；同范围部署或恢复最多 5 次；本地“修复 → 复验”最多 3 轮；同一命令的瞬时失败最多连续重试 3 次并计入对应总预算。

## Execution and Attempts

- 同一 Task 和授权范围内的命令组织、参数或本地脚本修复、只读状态查询、预算内重试及已授权恢复均在原 Task 维护。
- 包络内的普通失败必须连续推进诊断、局部修复和预算内重试，不得仅因失败创建新 Task、新审批、新 Agent 或重新独立预审。独立验收验证交付和目标结果，不是每条诊断命令的前置许可。
- 每次有副作用的执行必须在 Delivery Record 中记录 attempt、结果、已产生影响及原范围内修复；保留失败，不得只记录最终成功。
- 目标命令失败时必须保存安全失败回执：stage、关联命令或执行 ID、退出类别、已知影响和不含凭据或私密载荷的原因摘要；不得只记录笼统的 `failed` 或 `runtime_invalid` 而无法继续诊断。
- 一次失败不自动使 Task `Blocked`，也不得仅因一次失败创建新 Task。
- 授权仍为 `Pending`、预算耗尽、外部环境或依赖不可用、环境状态无法确认、需要人工决定或必须扩大边界时，Task 进入 `Blocked` 并记录解除条件。

## Reauthorization

目标环境或对象改变、固定输入或变更计划发生实质变化、资源新增/删除/替换、权限/凭据/数据/网络范围扩大、超出 attempt/成本/资源边界、恢复方式失效、新增生产或不可逆操作，或超出 Task/Sprint/本地 DP 时，必须停止并重新授权。

授权后的实质修改使 `Approval` 恢复为 `Pending`。只修正格式、链接或错别字且不改变含义时可保留授权，但应记录修订原因。

项目规则不得将部署执行包络内的普通诊断、局部脚本修复或预算内重试改为逐命令人工审批。确有更严格需要时，必须由项目 Owner 在关联 LDP 中说明具体实质风险、缩减范围和解除条件；不能只以“更严格”或一次失败作为理由。

## Evidence and Sensitive Information

- 普通项目记录只保存非敏感环境标识、操作类别、attempt、结果和证据引用。
- 不记录密码、token、私钥、秘密值、完整敏感配置、私有载荷或不必要的内部地址。
- 验收核对非敏感证明，不要求复制秘密值或私密原始输出。

## Acceptance and Target-Environment Gate

- Gate 验证阶段结果，不是每条环境操作的执行许可。
- 准备命令、修复脚本、状态查询和同范围重试不单独创建 Gate Task。
- 一项部署 Task 可以包含准备、执行、有限重试和恢复；Task Owner 交付后由独立 Acceptance Owner 验收。
- Sprint 需要硬件 / 目标环境 Gate 时，应在部署交付形成明确 build/commit、配置和非敏感环境标识后执行；模拟或本地结果不能替代。
