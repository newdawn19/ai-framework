# 项目知识库治理合约

## 1. 定位与边界

知识库保存项目可复用的来源、事实、解释、置信度与争议。它不保存密码、token、客户私有数据或未经授权的受限内容，也不能代替本地 DP、Sprint、Task 或验收证据。

知识证据需要改变已接受决定时，按共享合约的决策流程处理。

## 2. 默认结构与事实源

目标工程 `ai-framework.lock` 保存知识库逻辑路径；`./tools/ai-framework path` 将它解析到主工作树的公共 Agent 工作区。下文以 `<knowledge-path>` 表示该命令返回的知识库实际路径：

- `<knowledge-path>/raw/`：Bootstrap 默认创建；保存不可变的原始来源或允许保存的来源快照。
- `<knowledge-path>/source-manifest.yaml`：来源登记、状态、版本、校验与关联页面的唯一事实源。
- `<knowledge-path>/wiki/index.md`：查询入口与页面导航。
- `<knowledge-path>/wiki/topics/`：综合多个知识点的主题页面。
- `<knowledge-path>/wiki/cards/`：单一、精确、可独立引用的知识结论。
- `<knowledge-path>/wiki/archive/`：已被取代的历史页面，不作为当前有效结论；历史追溯时可以读取，但必须检查其取代者。
- `<knowledge-path>/log.md`：摄入、更新、冲突处理、归档与 Lint 的追加审计记录。
- `raw/` 随 Bootstrap 创建并包含使用说明；`wiki/topics/`、`wiki/cards/` 和 `wiki/archive/` 在首次需要存放对应内容时按需创建，不要求为保留空目录提交 `.gitkeep`。

## 3. 来源规则

- 来源快照写入后不可修改；修正、补充和解释写入 Wiki。来源更新应新增版本，并在 Manifest 中建立双向取代关系。
- 每个来源必须登记唯一 ID、类型、安全路径或受控位置、作者、发布日期、获取日期、版本、状态、权威性、可靠性、敏感等级、许可、存储策略、可用校验值与关联页面。确实未知的字段可以为 `null`，但必须说明原因，不得猜测。
- 可提交快照使用 SHA-256 或项目声明的等价校验；网页等可变外部来源记录获取时间，能合法保存时创建快照，不能保存时使用 `metadata-only` 并说明限制。
- 大型、私有、受版权限制或不得提交 Git 的来源只登记允许保存的非敏感元数据和受控位置标识，不复制原文，也不记录含 token、私有地址或客户信息的定位符。
- 单一权威一手来源可以形成知识页面；来源数量不能替代权威性、适用版本和直接证据。

## 4. 摄入与整合流程

1. 登记来源并标记 `pending`，不在登记前将未知内容批量提交 Git。
2. 检查范围、敏感性、许可、存储策略、权威性、版本与适用环境；为允许保存的快照计算校验值。
3. 搜索 Index、Topic 和 Card，避免重复页面。
4. 更新现有页面，或为可独立回答的问题创建 Card；Topic 只组织和综合，不复制所有 Card 细节。
5. 为关键参数、安全结论、协议和高风险主张提供段落级或句子级来源，使用 `[source-ID §section]`；没有章节时使用页码、段落、表格、时间码或其他稳定定位。
6. 更新 Manifest、Index 和变更日志，将来源标记为 `processed`、`rejected` 或 `superseded`。

## 5. 冲突、置信度与版本

- 新来源不能仅因日期更晚就覆盖旧结论；必须比较来源权威性、版本、适用条件、直接性和发布日期。
- 真冲突保留双方陈述、日期、版本与来源，页面标记 `contested: true`，并记录 `open → under-review → resolved / retained` 状态、Conflict Owner、审查结论和日期。
- 来源使用 `authority` 和 `reliability` 描述来源本身；知识页面的 `confidence` 综合来源权威性、直接支持程度、版本适用性、交叉验证与冲突情况，不按来源数量机械计算。
- 已完全取代的页面移入 Archive，保留 `superseded_by`，不得直接删除导致历史链接失效。

## 6. 查询与健康检查

- 查询路径为 `index → topic/card → source`；普通只读查询不修改日志。
- 精确参数、高风险判断、冲突、低置信度或证据不足时，必须回到原始来源核验。
- Lint 至少检查死链、孤立页面、Index 完整性、元数据、未登记来源、过时版本、争议、低置信度、页面大小与标签词表。
- Lint 还必须检查缺失校验/许可处置、失效的来源定位、未闭合取代关系，以及高风险主张是否具有精确引用。
- Lint 结果按严重程度报告；只有实际修复、状态变化或正式检查记录才追加日志。

## 7. 命名与内容粒度

- 文件名使用小写 kebab-case；长期知识页面按领域命名，不包含 Sprint 或 Task 编号。
- Card 只表达一个可独立引用的明确结论；Topic 负责关系、背景与导航。
- 交叉链接必须有真实语义，不为了满足数量要求创建无关链接。

## 8. 模版
- Topic 和 Card 使用 `<agent-workspace>/templates/knowledge/` 中的模板创建。
